## 用户故事

作为正在梳理论文主题的用户，我希望 Agent 在完成主题梳理并登记待办 issue 后，根据主题内容生成论文编写计划。计划应说明背景、研究问题与范围、写作大纲和各章职责，并列出可使用的文献、相关段落位置及摘要和文献对整篇研究的贡献，为后续写作提供依据。

## 触发与前置条件

- 用户：“帮我梳理论文主题。”
- 按 US-001 完成主题内容梳理。
- 无法澄清或用户明确延后考虑的问题已经登记为 issue；登记待办后进入计划生成，不要求所有 issue 均已关闭。

## Agent 行为与计划内容

1. 根据梳理得到的主题内容生成论文编写计划。
2. **主题与背景**：说明论文主题及其背景，定义论文要解决的问题内容与问题范围。
3. **论文写作大纲**：定义大纲框架，逐章规定该章节描述的内容概述。
4. **文献列表**：汇集以下来源的文献：用户已下载的本地文献、用户指定的文献，以及 Agent 通过多个数据源搜索、查找并验证来源的文献。
5. **逐篇文献贡献**：记录与用户论文问题相关的可引用段落位置、段落内容摘要，以及该文献对整篇论文研究的贡献。

## 文献列表的信息要求

| 信息 | 要求 |
|---|---|
| 文献身份 | 能识别具体文献，例如题名、作者、年份；具体格式未在本故事中限定 |
| 来源与核验依据 | 区分本地、用户指定、Agent 检索所得；检索所得文献需有可追溯的来源验证依据 |
| 可引用段落位置 | 指向与论文问题相关的具体段落，例如原文页码及章节/段落编号，或稳定网页的标题与段落定位 |
| 段落内容摘要 | 摘要与所定位段落对应，说明其与用户论文问题的关系 |
| 整篇研究贡献 | 说明该文献如何支持整篇论文研究，例如背景论据、理论框架、方法依据或分析视角；这些是说明方式示例，不限定贡献类型 |

文献来源经过验证与相关段落已经核对是两项不同的信息，不能以确认文献存在代替对可引用段落的核对。

## 验收条件

- 主题梳理完成、待办 issue 登记后，生成可供后续写作使用的论文编写计划。
- 计划包含主题背景、研究问题定义和范围，与主题梳理结果一致；仍待澄清的信息关联对应 issue，不冒充已确定内容。
- 计划包含大纲框架，每一章都有内容概述。
- 文献列表支持本地已下载、用户指定、Agent 多数据源检索三类来源；本次实际存在的文献按来源列出，不要求每次均具备三类文献。
- Agent 检索所得文献有来源核验依据，不能将未经核验的搜索结果标记为已验证文献。
- 每篇列入计划的文献说明其对整篇论文研究的贡献，并记录相关可引用段落的位置与摘要。
- 缺少全文或无法核对段落时，明确记录信息缺口及对应待办 issue，不能虚构位置、摘要或贡献依据，也不能把未核对内容标为可引用。
